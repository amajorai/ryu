# ryu-hardware

Ryu Hardware Protocol (RHP v1.1) node backend, an extracted **Core capability crate**.
It is the node half of the protocol in `apps/hardware/PROTOCOL.md`: Ryu devices
(watch / necklace / desk, all ESP32-S3) talk to a node over a WebSocket, either
directly over WiFi (Mode B) or relayed by the mobile app over BLE (Mode A). Devices
paired with v1.1 run an end-to-end `Noise_XX_25519_AESGCM_SHA256` session inside that
socket, so a relaying phone only ever sees ciphertext. v1 devices keep the legacy
plaintext session until they are re-paired.

## Role in the decomposition

A primitive lifted out of `apps/core`. It owns the paired-device registry, the token
lifecycle, the node identity, pairing (legacy and v2), the RHN secure-session layer,
device capability validation and invoke, the audio codec edge, the per-connection
realtime session state machine, the display-nudge loop, and the device-registry +
TRMNL display HTTP surface.

The crate has **zero dependency on `apps/core`**, and it links neither the dashboards
nor the meetings app: both couplings are inverted through in-crate trait seams
(`feed::DashboardFeed`, `ingest::MeetingIngest`) that Core implements. The node key is
sealed at rest through `identity::NodeKeySealer`, which Core also implements.

## Layout / key modules

- `protocol`: serde mirror of PROTOCOL.md §3 (including the v1.1 capability
  messages), the pairing REST bodies, and two-step `parse_client_msg`.
- `noise`: hand-written Noise rev 34 XX (`Noise_XX_25519_AESGCM_SHA256`), no `snow`.
- `secure`: RHN outer frames, `ServerHandshake` (node) and `ClientHandshake` (device,
  for tests and interop), and the owned `SendHalf` / `RecvHalf` (fragmentation,
  rekey, limits, error codes).
- `identity`: the node's static X25519 key, its fingerprint, and `NodeKeySealer`.
- `pair_crypto`: pairing v2 commitment, transcript, SAS, confirm tag, credential seal.
- `pairing`: legacy `pair` and the v2 `begin_pair` / `reveal_pair` / `confirm_pair` /
  `cancel_pair` flows, with `PairError` codes and status hints.
- `capability`: capability descriptor validation, JSON-schema translation, argument
  checks and agent tool naming (rules shared with the C firmware).
- `store`: device registry (SQLite) with idempotent migrations: paired devices,
  device and relay token hashes, pinned keys and the level-2 ratchet, pending
  pairings, consumed pairing nonces, and the sealed node identity.
- `codec`: the Opus/WAV codec edge, so the rest of Core sees PCM/WAV.
- `session`: the realtime session state machine (audio buffering + ambient meetings
  bridge) and `session::live`, the live connection registry with a priority control
  channel, per-connection capabilities and `invoke` / `complete`.
- `nudge`: the live display-nudge loop (dashboard change → device re-poll).
- `api`: device-registry CRUD (`/`, `/:device_id`) + TRMNL display
  (`/:device_id`, `/:device_id/image`) axum routers.

The golden vectors in `tests/vectors/` (generated by `tools/hardware/gen-rhp-vectors.py`)
are the cross-language contract; the unit tests recompute every value, and the generator's
`--check` compares them with an independent Python oracle.
`tests/c_interop.rs` drives the C device simulator when `RHP_DEVICE_SIM` points at it,
and prints `c_interop: skipped` otherwise, unless `RHP_REQUIRE_DEVICE_SIM=1` (set in CI),
which turns a missing simulator into a failure.

## What stays Core-side (consumers of this crate's types)

- The **public ws ingress** (`server::hardware_ws`): a per-device Bearer that the global
  `RYU_TOKEN` `require_auth` cannot gate, authenticated before any DH and driven
  through `secure`.
- The **protected pairing routes** (`server::hardware_public`): legacy `pair`,
  `pair/{begin,reveal,confirm,cancel}` and `identity/reset`, plus mesh/SSRF-guarded
  node-URL resolution.
- The **chat-turn orchestration** (welded to Core's `run_text_turn` / voice ASR / TTS
  session loop) and the reserved `device` MCP server for capabilities.

## Placement (Core vs Gateway)

The device registry, token lifecycle, and realtime session decide *what runs* → Core.

## Consumed as

Compiled-into-core crate (non-optional path dependency): the codec is reused by the
voice module and the store backs `ServerState` in every build.
