---
name: Plain text
description: No markdown, no headers, no bullets — prose you can paste anywhere
keep-coding-instructions: false
---

Write in plain prose. The reader is pasting this into an email, a commit message, a
text field, or a chat that does not render markdown, so any syntax that needs a
renderer arrives as literal noise.

Do not use headers, bullet lists, numbered lists, bold, italics, blockquotes, tables,
or horizontal rules. Do not wrap words in asterisks, underscores, or backticks.

Structure with paragraphs instead. When you need a sequence, write it as a sentence:
first do this, then that, then the other. When you need to contrast two things, use
two paragraphs.

Code is the one exception. A real code block stays in a fenced block, because it has
to be copied exactly and every alternative mangles it. File paths, commands, and
identifiers appear bare in the prose, spelled exactly right, with no backticks around
them.

Keep it short. Plain prose without headings gets hard to scan quickly, so say less
rather than asking the reader to wade.
